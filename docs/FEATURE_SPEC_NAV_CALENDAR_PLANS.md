# Love Points 导航、生活日历与周期计划功能文档

> 文档状态：待确认，确认后进入开发
> 版本：V3 功能增量
> 更新日期：2026-08-28
> 适用范围：微信原生小程序、CloudBase 云函数、本机体验模式

## 1. 背景与目标

当前版本已经具备自定义页头、生活日历和任务审批闭环，但存在三类体验与业务问题：

1. 二级页面没有统一的返回入口，用户进入详情或编辑页面后不容易判断如何返回。
2. 日历只用圆点表示情绪，不能直接看到当天的情绪；选中日期后，记录内容又会直接铺在日历下方，隐私感和浏览效率都不理想。
3. 任务只有“个人任务 / 共同任务”分类，没有“每日 / 每周 / 长期”周期。任务完成后永久结束，无法按天或按周自动更新。

本次增量的目标是：

- 为所有二级页面提供一致、可靠的返回交互。
- 在月历日期下直接显示可见的情绪，同时将当天记录收起，只有用户主动点开后才展示。
- 在保留个人积分 / 共同积分规则的基础上，新增每日、每周、长期三类计划，并让每日、每周计划按周期独立结算和更新。

## 2. 名词与边界

### 2.1 两个互不替代的任务维度

任务创建时同时选择两个维度：

| 维度 | 选项 | 决定内容 |
|---|---|---|
| 积分归属 | 个人、共同 | 审批通过后积分进入个人账户还是共同账户 |
| 计划周期 | 每日、每周、长期 | 任务多久生成一次新周期、何时结算、完成后是否自动更新 |

例如，“每天喝水”可以是“个人积分 + 每日计划”，“每周约会”可以是“共同积分 + 每周计划”。

### 2.2 本次包含

- 自定义页头返回按钮和异常返回兜底。
- 日历格内的情绪表情、事件 / 经期提示、当天记录抽屉。
- 每日、每周、长期计划的创建、列表展示、提交、审批、结算和周期更新。
- 本机体验模式与云端模式保持相同行为。
- 旧任务数据迁移和自动化测试。

### 2.3 本次不包含

- 自定义复杂重复规则，例如“每月第二个周二”或“每隔三天”。
- 连续打卡、连续天数奖励、漏签补签和提醒通知。
- 任务编辑、删除、暂停、日历历史统计和情绪趋势图。
- 因未完成任务扣分。

这些能力可在周期模型稳定后继续扩展。

## 3. 功能一：统一返回导航

### 3.1 页面规则

- 五个底部 Tab 根页面不显示返回按钮：首页、任务、社区、文档、我的。
- 启动页不显示返回按钮。
- 从根页面进入的二级、详情、编辑、确认页面，页头左侧显示返回按钮。
- 返回按钮位于微信胶囊按钮的安全区域之外，点击热区不小于 44 × 44 px。
- 页面标题与副标题保持现有层级；有返回按钮时，标题区域为按钮预留空间，不发生遮挡或跳动。

需要返回按钮的现有页面包括：

- 生活日历、记录新建 / 查看 / 编辑。
- 任务提交、任务审批。
- 积分中心、奖励列表、奖励详情、已兑换奖励。
- 社区发布。
- 文档新建 / 编辑。
- 个人资料编辑、设置。
- 邀请创建、输入短码、绑定确认。
- 等待解绑、确认解绑。

### 3.2 返回行为

1. 页面栈中存在上一页时，执行普通返回，保留上一页的筛选和滚动位置。
2. 页面由分享、扫码或冷启动直接打开，没有上一页时：
   - 已绑定且已完成资料：回到首页。
   - 未完成个人资料：回到资料填写页。
   - 未绑定：回到启动页。
3. 保存、删除等成功动作沿用返回上一页；审批后跳转积分中心等明确业务跳转不强制改成普通返回。

### 3.3 验收标准

- 任一二级页面都能在页面内找到返回入口。
- 连续进入三级页面时，逐级返回正确。
- 分享直达页面点击返回不会停留在空白页或无反应。
- iPhone 刘海屏、灵动岛和常规屏幕下均不与状态栏、胶囊按钮重叠。

## 4. 功能二：生活日历交互调整

### 4.1 月历格展示

每个日期格默认只展示以下摘要，不直接展示记录标题、备注或经期详情：

- 日期数字。
- 情绪记录：在日期数字下显示实际情绪表情，例如 `😊`、`😌`。
- 同一天有自己和伴侣的可见情绪时，最多显示两个表情；每人只取当天最新一条情绪记录。
- 事件记录：保留一个小型蓝色提示点。
- 经期记录：保留一个小型红色提示点，仅基于当前用户有权查看的记录生成。
- 当天为选中态时，表情和提示点仍需清晰可辨。

隐私规则保持不变：自己的记录都可见；伴侣仅主动共享的记录可见；未共享的经期和其他记录不会通过图标、数量或空位被推断出来。

### 4.2 打开当天记录

- 页面初次进入只显示月历，不在月历下方直接铺开当天记录内容。
- 点击日期后，将该日期设为选中态，并从页面底部打开“当天记录”抽屉。
- 抽屉顶部显示日期和可见记录数量。
- 抽屉内按创建时间倒序显示记录摘要：情绪表情 / 类型、记录人、可见范围和标题摘要。
- 点击自己的记录进入可编辑状态。
- 点击伴侣共享的记录进入只读详情，能够查看完整标题和备注，不出现编辑、删除按钮。
- 没有记录时，抽屉显示空状态和“记录这一天”按钮。
- 有记录时，抽屉也保留“新增一条记录”入口。
- 点击遮罩、向下关闭或再次点击已选日期，可关闭抽屉；关闭后不泄露记录内容。

### 4.3 月份与刷新规则

- 切换月份后默认选中：当月为当前月份时选中今天，否则选中当月 1 日。
- 点击上月 / 下月补位日期时，切换到对应月份并打开该日期的当天记录。
- 新增、编辑或删除记录返回日历后，自动刷新当前月份，情绪表情和提示点立即更新。
- 下拉刷新保留当前选中月份和日期。

### 4.4 验收标准

- 月历日期下能直接看到保存的实际情绪表情，不再只显示“情绪圆点”。
- 未点击日期时，页面不显示当天记录标题和备注。
- 点击有记录日期后能查看完整记录；伴侣共享记录可读但不可编辑。
- 私密记录不会被伴侣看到，也不会在伴侣日历上产生任何标记。
- 同一日期有多条情绪时，日历格不溢出、不挤压日期数字。

## 5. 功能三：每日、每周、长期计划

### 5.1 计划分类

| 分类 | 当前周期 | 结算与更新 | 完成后的行为 |
|---|---|---|---|
| 每日计划 | 当天 00:00–次日 00:00 | 每天结算一次；新一天首次打开相关页面时自动生成当天周期 | 昨天的结果保留，今天恢复为待完成 |
| 每周计划 | 周一 00:00–下周一 00:00 | 每周结算一次；新一周首次打开相关页面时自动生成本周周期 | 上周结果保留，本周恢复为待完成 |
| 长期计划 | 创建后直到完成 | 不自动结算、不自动更新 | 审批完成后保持已完成 |

周期边界统一使用 `Asia/Shanghai` 时区，避免客户端时间与云函数 UTC 时间不一致。

### 5.2 “结算”的准确含义

- 结算只关闭已经结束的周期，不会因为时间到达自动发积分或扣积分。
- 周期内审批通过：记为“已完成”，发放一次积分。
- 周期结束时仍为待完成或已驳回：记为“未完成”，不发积分；新周期正常生成。
- 周期结束时仍为待审批：保留为“待审批”，可在新周期开始后继续审批，同时为每日 / 每周计划生成新的当前周期。
- 延迟审批通过时，积分归属旧周期，不改变新周期状态。
- 同一计划同一周期最多产生一笔任务积分流水，重复点击审批不会重复加分。

这样可以保证“每天更新”不会覆盖昨天尚未处理的提交。

### 5.3 创建计划

现有“新建任务”面板新增“计划周期”字段：

- 每日：每天可完成一次。
- 每周：每个自然周可完成一次。
- 长期：仅需完成一次。

创建时继续填写：

- 任务名称。
- 任务说明。
- 完成积分。
- 积分归属：个人 / 共同。
- 执行人：我 / 对方。
- 计划周期：每日 / 每周 / 长期。

默认选择“长期”，保证旧版本使用习惯和现有一次性任务语义不被突然改变。

### 5.4 任务列表

任务视图增加周期筛选：

- 今日：显示每日计划的当天周期。
- 本周：显示每周计划的本周周期。
- 长期：显示未结束和已完成的长期计划。
- 待审批：显示当前用户可处理的所有待审批周期，包括已经跨日 / 跨周的旧周期。

每张任务卡增加周期信息：

- 每日计划：`每日 · 今天`。
- 每周计划：`每周 · 本周`。
- 长期计划：`长期`。
- 跨周期待审批：显示具体周期，例如 `8 月 27 日 · 待审批` 或 `8 月 24–30 日 · 待审批`。

顶部统计改为当前筛选下的“待完成”和“待审批”，避免把历史已完成周期计入进行中。

### 5.5 首页展示

- “今日任务”优先显示今日每日计划。
- 没有每日计划时，依次显示本周未完成计划、长期未完成计划。
- 已完成的今日计划可以显示完成态，但不重复提交。
- 存在需要当前用户审批的旧周期时，首页待处理区域继续提示，不因跨日隐藏。

### 5.6 提交与审批

- 进入提交页时明确显示计划分类和当前周期。
- 每日 / 每周计划只能提交当前周期；旧周期未提交的任务不允许补交。
- 每个周期仅允许一个有效提交；被驳回后可在周期结束前补充说明并重新提交。
- 周期结束后，旧周期的“待完成 / 已驳回”变为未完成，不再允许提交。
- 待审批记录即使跨周期，仍允许指定审批人通过或驳回。
- 审批结果、积分流水和周期状态在同一服务端事务中完成。

### 5.7 旧数据迁移

- 没有计划周期字段的旧任务统一迁移为“长期计划”。
- 旧任务现有状态、提交记录和已发积分保持不变。
- 云端首次读取旧任务时兼容缺失字段；部署脚本或惰性迁移补齐 `planType: long_term`。
- 本机缓存读取时执行同样迁移，用户不需要清空本地数据。

### 5.8 验收标准

- 能创建每日、每周、长期三种计划，且与个人 / 共同积分组合使用。
- 每日计划在新的一天出现新的待完成周期，昨天记录仍可追溯。
- 每周计划每周一生成新周期；长期计划完成后不会自动重置。
- 跨日待审批不会丢失，也不会阻止当天新周期生成。
- 同一周期重复审批不会重复加积分。
- 旧任务升级后仍可查看和操作，默认显示为长期计划。

## 7. 数据模型建议

### 7.1 `tasks`：计划模板

在现有字段上新增：

| 字段 | 类型 | 说明 |
|---|---|---|
| `planType` | `daily` / `weekly` / `long_term` | 计划周期，旧数据默认 `long_term` |
| `timezone` | string | 首版固定 `Asia/Shanghai` |
| `enabled` | boolean | 是否继续生成周期，首版创建后恒为 true |
| `startDate` | string | 计划生效日期 |

每日和每周计划的实时状态不再直接写回模板，避免新周期覆盖旧周期。

### 7.2 `task_cycles`：任务周期实例

新增集合保存每一次日 / 周 / 长期周期：

| 字段 | 类型 | 说明 |
|---|---|---|
| `taskId` | string | 关联计划模板 |
| `coupleId` | string | 情侣空间隔离 |
| `cycleKey` | string | 每日如 `2026-08-28`；每周如 `2026-W35`；长期为 `lifetime` |
| `periodStart` / `periodEnd` | date | 周期边界 |
| `status` | `todo` / `pending` / `approved` / `rejected` / `missed` | 本周期状态 |
| `latestSubmissionId` | string / null | 当前提交记录 |
| `settledAt` | date / null | 周期结算时间 |
| `createdAt` / `updatedAt` | date | 审计时间 |

唯一性由 `coupleId + taskId + cycleKey` 保证。周期采用按需生成：用户打开首页、任务列表或进行提交时，由云函数补齐当前周期，不依赖定时任务也能正确更新。

### 7.3 `task_submissions` 与积分流水

- 提交记录新增 `taskCycleId` 和 `cycleKey`。
- 积分流水幂等键继续基于提交记录，确保每个周期最多发放一次。
- 查询待审批时直接查询所有 `pending` 周期，不限制为当前日期或当前周。

## 8. 异常与边界处理

- 客户端日期不可信：周期边界由云函数服务器时间计算。
- 用户跨 00:00 停留在任务页：下次回到前台或主动刷新时自动结算并切换到新周期。
- 网络中断：不在客户端假定结算成功；重新请求后以云端周期状态为准。
- 重复打开页面：周期唯一索引和事务保证不会生成两个相同周期。
- 旧周期待审批与新周期同时存在：列表可分别展示，审批必须携带 `taskCycleId`。
- 伴侣共享记录被取消共享或删除：日历刷新后立即移除对应表情 / 标记，已打开的只读详情重新请求失败时提示记录不可见。

## 9. 测试与发布要求

### 9.1 自动化测试

- 页头：有上一页、无上一页、Tab 根页三种返回场景。
- 日历：单情绪、双方情绪、多情绪、私密记录、跨月日期和空日期。
- 周期：同日重复打开、跨日、跨周、旧周期待审批、新周期生成、旧任务迁移。
- 积分：每周期仅发一次；延迟审批归属旧周期；驳回不发积分。
- 本机模式与云函数模式覆盖相同核心流程。

### 9.2 发布前人工验收

- 微信开发者工具模拟器检查常规屏、刘海屏和安全区。
- 使用两个真实微信账号验证私密记录、共享记录和跨账号审批。
- 将设备时间停留在跨日边界附近只用于界面观察；最终周期正确性以云端服务器时间测试为准。
- 执行项目根目录 `npm run verify`，并确认新增数据库集合与索引已部署。

## 11. 确认项

本文档先按以下默认规则进入开发；如需调整，应在开发前确认：

1. 每周从周一 00:00 开始，到下周一 00:00 结算。
2. 跨日 / 跨周仍待审批的提交可以继续审批，同时新周期正常生成。
3. 未完成计划不扣分，只记录为未完成。
4. 旧任务全部迁移为长期计划。
5. 日历最多显示自己和伴侣各一个最新情绪表情，详细记录必须点开日期后查看。
