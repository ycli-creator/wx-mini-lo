## 1. 微信开发者工具

1. 打开微信开发者工具并登录。
2. 进入“设置 → 安全设置”，开启“服务端口”。
3. 导入包含 `project.config.json` 的仓库根目录 `wx-mini-lo`。
4. 确认 `project.config.json` 使用当前个人小程序 AppID `wx2f2b626c271ccbcc`。
5. 选择“工具 → 构建 npm”，确认生成 `miniprogram_npm/tdesign-miniprogram`。

AppID 可以写入项目；AppSecret 不可以写入项目。

## 2. CloudBase 云开发

1. 在仓库根目录执行 `npm run verify:deployment-config`，确认 AppID 一致、`CLOUD_ENV_ID` 已配置，并在开发者工具核对目标环境。
2. 对照 `cloudfunctions/database-schema.json` 回读现有环境的 31 个集合、54 个自定义索引，确认业务集合仅管理端可读写。可通过云开发控制台核对，或用带 `wechatide` 的 Nightly 运行 `npm run verify:cloudbase-structure` 检查集合及索引。若命令未加入 PATH，可设置 `WECHATIDE_BIN` 为其可执行文件路径。
3. 备份并对比现有 `api` 云函数。重点确认 `diary.scope`、`diary.history`、`health.statistics` 和日记/健康心情双向联动是否与本地一致。新版编辑器在保存前调用 `diary.scope`，旧后端缺此接口时保存会被拦截。
4. 如需更新现有 `api`，保留云端已有改动及运行配置，部署后回读函数状态和代码，再生成供联调的客户端预览。

- 启动页、邀请、首页、任务、积分、奖励、文档、设置和解绑页面均无编译错误。

## 4. 两名微信用户真机验收

1. A 创建邀请，B 输入 6 位短码，A 同意绑定。
2. B 提交任务，A 审批；连续点击审批不会重复加分。
3. 创建奖励并兑换；余额不足时禁止兑换，重复点击不会重复扣分。
4. 发起退款，对方通过后只返还一次积分。
5. A 编辑文档时，B 只能只读；A 保存或离开后 B 可以获得编辑锁。
6. A 发起解绑时数据仍保留；B 同意后情侣空间数据清空，双方可以重新绑定。
7. A 发布一条纯文字帖子；B 在自己的手机上能看到，任意第三方账号都看不到；帖子没有确认环节，保存后双方立即可见；图片或视频应被客户端和服务端明确阻止。
8. A 新建一条仅自己可见的经期记录，B 不可见；A 新建双方可见事件后，B 可在同一天看到。
9. 新建“双方每天各自完成”的待办，A、B 分别完成后双方进度颜色正确，积分分别到账，且只有双方完成后任务才结束。
10. 双方分别编辑同一待办并添加照片，详情页能查看修改、完成和照片记录；大任务每一步均可添加照片。
11. 发布人编辑帖子时标题与正文分别回填和保存；保存后双方立即看到最新内容，不存在待确认状态。
12. A 保存一篇测试日记，重启小程序确认内容和编辑设置回显，修改后检查历史版本。B 的日记列表中没有 A 的内容。
13. A 从日记编辑当天心情，健康日历同步显示。再从健康日历修改同一天的心情，检查日记、统计和重启后的显示，B 的记录无变化。
