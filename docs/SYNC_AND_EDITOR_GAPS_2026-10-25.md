# 同步问题与日记编辑器差距

日期：2026-10-25。记录用户预览后反馈的“许多功能未同步”和编辑器与原版不一致。

## 初始诊断：已证实的同步问题

微信开发者工具已登录，可查询目标环境 `cloud1-d8grmd06k6e68e512`，其下 `api` 函数为 Active、Nodejs16.13、20 秒超时。云端代码已下载到 `analysis/diary/cloud-backup-20261025` 独立备份。

线上 `index.js` 没有 `diary.list`、`diary.save`、`health.read`、`health.change`；本地客户端已经调用这些 Action。现有线上路由会对这些操作返回 `ACTION_NOT_FOUND`。所以开发预览上传成功，并不意味着新日记和健康日历能保存或同步。

首页、待办、积分、文档等多页调用 `home.summary` 并在失败后显示通用“未同步”。不能仅凭这行界面文字确认它们都由缺少日记接口引起。已向用户询问具体页面和短暂弹出的错误文本。模拟器自动化连接成功，但 AppService 调用未在 45 秒内返回；本轮未获得这些页面的真实接口失败码，不将连接超时冒充云函数超时。

线上版本还存在本地版本没有的分区读取、请求用户复用和性能日志等优化。后续部署应先合并差异，保留线上有效改进；不可直接用当前本地旧基线覆盖线上。

## 编辑器差距及原因

上轮实现擅自收窄为文字日记核心功能，并采用项目自身的表单；这不等于用户要求的原版编辑体验复刻。当前仅完成的标题/正文、心情天气、分类标签、显式草稿等，不能覆盖原版完整编辑器。

本轮新增 REA 证据 `analysis/diary/method-record.RecordActivity-onCreate.json`，目标 SHA-256 与原附件一致；`onCreate` 明确使用 `R.layout.activity_record`，并读取原版行距、同步类型、日期与分类标签等初始化状态。结合此前方法证据，已确认：

- 图片、本地音频和绘图均有编辑入口；媒体也是退出时内容变化判断的一部分。
- 菜单包含分类、历史、隐藏/锁定、Markdown、模板、标题显示开关等。
- 原版有自动保存与草稿恢复路径；当前小程序采用显式保存和离开提示，行为不同。
- 当前未运行原 APK，因此精确布局、所有手势及完整编辑结果仍不能宣称已一致。

这些缺口应按原版编辑器继续取证和补齐，不应把几个表单字段相同表述成已经完成复刻。
