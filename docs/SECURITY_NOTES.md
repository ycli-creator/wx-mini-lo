# Love Points 安全说明

> 当前部署状态（2026-09-02）：本地结构已扩展为 28 个集合、52 个自定义索引，社区治理改动尚未部署；云端仍运行此前已验证的 `0.3.0` 版本。

## 已落地的安全边界

- 客户端不直接读写 CloudBase 业务集合，所有业务写操作统一经过 `api` 云函数。
- 用户身份只读取小程序调用上下文中的 OpenID，不接受客户端传入用户 ID 冒充身份。
- 每个业务 Action 都校验当前 OpenID 是否属于对应 `coupleId`。
- 任务审批、奖励兑换和退款使用数据库事务同时更新账户、业务状态和不可变积分流水。
- 重复任务审批、重复退款由服务端状态机阻止；奖励兑换额外使用客户端幂等键和确定性兑换记录 ID。
- 文档采用五分钟事务编辑锁；保存时必须仍由当前用户持有有效锁，避免并发覆盖。
- 解绑在双方确认前不删除数据；确认后分批清理情侣空间业务集合，最后用事务解除双方关系，失败时可安全重试。
- 短码只在创建响应中返回，数据库仅保存 SHA-256 摘要与有效期。
- 个人资料中的公开昵称、地区和爱好，以及社区文字，在服务端通过 `security.msgSecCheck` 检查；检查服务不可用时拒绝发布。
- 社区帖子必须由情侣双方确认后才进入公开 Feed；未确认帖子只对当前情侣空间可见。
- 社区正式版默认降级为纯文字发布；图片和视频入口及服务端写入均关闭，接通媒体内容审核前不得恢复。
- 公开确认绑定具体内容版本；任何一方开启一键不展示或解除绑定都会撤回该情侣空间的公开帖子。
- 公开帖子支持举报、共同撤回和作者软删除，旧分享入口会重新校验帖子实时公开状态。
- 性别、地区和爱好不会随社区帖子公开，社区只使用昵称、头像和情侣组合名称快照。
- 情绪、事件与经期记录按记录保存 `self/couple` 可见范围；经期等敏感记录默认仅自己可见，伴侣不可读取。

## 官方 SDK 依赖审计

云函数使用当前 `wx-server-sdk@4.0.2`。截至 2026-08-24，`npm audit` 会报告来自官方 SDK 内部旧版 `axios`、`lodash.set` 和 `lodash.unset` 的 1 个中危与 5 个高危传递依赖告警；`npm audit fix` 没有非破坏性修复方案，强制修复会降级到实际包含更多严重告警的旧 SDK 2.5.3，因此未采用。

本项目不把用户输入作为外部 URL、代理地址、请求头或 SDK 配置，也不从云函数发起用户可控的 HTTP 请求，已经降低这些告警中 SSRF、代理绕过和请求头注入路径的可利用面。正式部署前仍应重新检查腾讯发布的 SDK 更新，并优先升级到修复传递依赖的官方版本。

## 部署要求

- CloudBase 集合权限设为禁止客户端直接读写。
- 不在仓库、聊天或客户端代码中写入 AppSecret、CloudBase 密钥或上传私钥。
- 云函数仅允许小程序端调用，不向 HTTP 或 Web 混合入口开放。
- 部署后使用两名测试用户检查跨情侣空间越权、重复点击、积分一致性和解绑清理。
- 正式开放公开社区前必须在微信公众平台完成隐私保护指引配置，并建立 `community_reports` 的人工处理流程。图片和视频仍保持关闭；当前文字安全检查和情侣共同确认不能替代未来所需的媒体审核。
